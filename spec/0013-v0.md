# 13. First version (v0) and roadmap

**Planned** · updated 2026-10-19 · related: [spec 1](0001-purpose.md), [spec 2](0002-architecture.md),
[spec 5](0005-file-formats.md), [spec 6](0006-table-formats.md), [spec 7](0007-engines.md),
[spec 8](0008-query-trace.md), [spec 9](0009-checks.md)

## Summary

What the first usable version contains and the order after it. v0 proves the whole path from a bucket to a byte on
the two most common formats (Parquet files and Iceberg tables) and one engine; later steps add formats and engines
behind the same traits.

## Design

### v0

- `lakeglass <url>`: local server and UI (spec 2, run modes); S3, S3-compatible, GCS, Azure, and local stores with the
  counting layer and cache (spec 3).
- Store map with detection for all table signatures in spec 4 (detected and labelled even before a format crate can
  open them).
- File anatomy and rows: Parquet, Arrow IPC, Avro (needed for Iceberg manifests).
- Tables: Iceberg (metadata tree, snapshots, schema history, files, deletes) and Delta Lake.
- Engine: DataFusion, with SQL over opened tables and file sets.
- Query trace for Iceberg tables and Parquet file sets.
- Checks: `files.small`, `files.row_group_size`, `files.missing_stats`, `files.no_page_index`, `layout.overlap`,
  `snapshots.many`, `metadata.manifests`, `deletes.backlog`.

### After v0, in order

1. DuckDB engine; engine comparison.
2. Hudi, Paimon, Lance, Vortex, ORC, Puffin; the remaining checks.
3. SSTables and logs: SlateDB, Fluss remote storage, RocksDB SST.
4. Catalogs (Iceberg REST, Glue, Unity Catalog, Hive Metastore) and DuckLake.
5. Browser-only mode (WASM).
6. Remote engines (Flight SQL, Trino, Spark Connect), Polars.
